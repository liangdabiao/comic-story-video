# 配音方案：单口相声音色（首选，已定）

> **结论先放这里：音色不再从公共音色里挑，用 `minimax/voice-design` 拿自然语言描述生成。**
> **片子是单口**——一个人说书，不要捧哏、不要第二个音色。
> 音色定一次，写进 `story.json`，七格全用同一个。

这条是实测跑通之后定下来的，不是推断。下面每条命令都真跑过。

---

## 0. 为什么不从公共音色里挑

| 事实 | 后果 |
|---|---|
| 公共音色 **303 个** | 按 `Chinese (Mandarin)` 前缀筛只看到 26 个，容易误以为就那么几个 |
| `tags` 字段全是坏的 | `Mature_Woman` 标「中文,男,中年」、`Sweet_Lady` 也标「男」——按标签挑等于瞎挑 |
| 全是「通用朗读」 | 没有一个是给曲艺调的，最接近的 `Humorous_Elder` 也只是「老年幽默」 |

所以「挑一个最像的」这条路走不通。**改成「描述一个出来」。**

## 1. 设计音色（一次约 1 分钱）

```bash
apiz generate "音色描述" \
  --model minimax/voice-design \
  --params '{"preview_text":"试听文本","voice_id":"xiangsheng01"}' \
  --wait --wait-timeout 3m --json
```

三个参数就是后台那三个「高级参数」：

| 参数 | 作用 | 注意 |
|---|---|---|
| `prompt`（位置参数） | 音色描述，自然语言 | 见 §2 |
| `preview_text` | 试听音频念的文本 | 计费 2 元/万字符；见 §3 |
| `voice_id` | 自定义音色 ID | 英文 + 数字，字母开头 |

`generate` 只回 `task_id`，**结果要去取**：

```bash
apiz tasks get <task_id> --json
```

```json
{
  "status": "completed",
  "result": {
    "voice_id": "xiangsheng01",
    "audio_url": "https://cdn-hk.51sux.com/minimax-voice-design/....mp3",
    "success": true
  }
}
```

`audio_url` 就是试听音频，先听一遍再决定要不要用。生成的音色会出现在
`apiz voices list` 的 `user_voices` 里。

## 2. 已验证可用的描述（照抄，只改细节）

```text
三十多岁的相声演员，男声。嗓音亮而脆，中气足，说话像在台上使活，字字咬得清楚。
语速偏快、有顿挫，句尾习惯往上挑，带着天津口音的机灵劲儿。语气夸张、爱逗哏，
说到得意处会突然加重、拖长。不是在念稿，是在跟台下的观众聊天。
```

这段出来就是「脆、亮、冲、有顿挫」，已经听过确认。

**它为什么有效** —— 九个要素，缺哪个都会往「播报」滑：

| 要素 | 这段里的写法 | 少了会怎样 |
|---|---|---|
| 年龄性别 | 三十多岁的相声演员，男声 | 模型自己猜，容易给青年播音腔 |
| 音色质感 | 嗓音**亮而脆**，中气足 | 写成「低沉富有磁性」→ 变悬疑解说 |
| 咬字 | 字字咬得清楚 | 含糊、吞字 |
| 语速 | 语速偏快、**有顿挫** | 只写「快」→ 变新闻快讯 |
| 语调走向 | **句尾习惯往上挑** | 相声的「劲儿」全在句尾，平了就死 |
| 口音 | 天津口音的机灵劲儿 | 普通话播音腔，没有曲艺地理锚点 |
| 情绪 | 语气夸张、**爱逗哏** | 平淡叙述 |
| 强弱 | 说到得意处会**突然加重、拖长** | 全程一个力度，等于没有重音 |
| 场景（否定句） | **不是在念稿，是在跟台下观众聊天** | 这条最要紧，直接排除朗读腔 |

**反面词表**（出现就把音色往错的方向拉走）：

`低沉` `富有磁性` `温柔` `亲和` `舒缓` `沉稳` `专业播报` `睡前` `治愈`

## 3. `preview_text` 别用后台默认

后台默认是新闻稿：

> 各位听众朋友们，大家好！今天我们来聊聊人工智能的发展现状和未来趋势……

拿它试听，你听到的是「**用相声音色念新闻**」，会误判成「音色不行」。

要写一段**自带节奏**的，把垫话、语气词、重复、停顿都塞进去：

```text
您猜怎么着？这事儿啊，得从头说起。五十九岁，一脚踹到惠州——惠州！
那地方在当时，不是城市，是终点站。
```

- 「您猜怎么着」= 垫话
- 「这事儿啊」= 语气词，试气口
- 「惠州——惠州」= 重复，试递进
- 「——」= 强制停顿，试顿挫

四十来个字，成本不到一分钱，但能听出这个音色**有没有顿挫**。

## 4. 合成：`speak` 直接用这个音色

音色定下来之后，合成**仍然走 `speak`**（同步、便宜、稳定）：

```bash
apiz speak "旁白文本" --model speech-2.8-hd \
  --voice xiangsheng01 --output-file audio/s1.mp3 --json
```

`story.json`：

```json
"tts": {
  "engine": "apiz",
  "model": "speech-2.8-hd",
  "voice": "xiangsheng01",
  "speed": 1.0
}
```

**`speed` 用 1.0，不要再配 `post_speed`。**

理由：相声的节奏由**文本和音色**给（垫话、重复、破折号），不靠压时间轴。
之前那套 `speed 1.30 + post_speed 1.15` 是为了把语速拉到 4.7 字/秒，
结果是把所有停顿时长等比缩短 —— 0.25 秒的气口被压到 0.21，
跨过了「0.15 秒以下算卡顿」那条感知线，气口没了，听感变成匀速念稿。
**那是为了时长牺牲节奏，现在不需要了。**

## 5. 情绪：`speak` 不支持，走 `t2a` 异步（进阶，可选）

`apiz speak` 只有 `--model / --voice / --speed / --output-file` 四个参数，
**没有 emotion**。要情绪得走模型接口：

```bash
apiz generate "文本" --model minimax/t2a \
  --params '{"voice_id":"xiangsheng01","text":"文本","emotion":"happy","pitch":1}' \
  --wait --wait-timeout 2m --json
# 再 apiz tasks get <task_id> --json → result.audio_url
```

字段是**顶层**的，不要套 MiniMax 官方的 `voice_setting` 结构（那样会 400：
「voice_id 是必填参数」）。

实测生效，同一句话只改 `emotion`：

| emotion | 时长 | 文件大小 |
|---|---|---|
| neutral | 7.45s | 120,948 |
| happy | 7.02s | 114,036 |
| angry | 7.92s | 128,436 |

三个 md5 全不同 → 参数**没有被静默忽略**。

**但它作用在整段，不是逐句。** 想让「包袱那一句」更冲，只能把那句单独合成、
再按时间轴拼回去（见 `comic-story.md` §8 气泡坐标那套的同一思路：分句，再排）。

> `comic_tts.py` 目前只走 `speak`，**没有接 emotion 通道**。要用就走上面的命令行，
> 或者后续给它加一个 `"emotion"` 字段分支。日常出片不需要它。

## 6. 硬约束（不知道会白跑）

| 约束 | 说明 |
|---|---|
| **音色 7 天不用自动删** | 临时音色，168 小时内未调用即删除。每周至少跑一次，或把 §2 那段描述存进项目里准备重建 |
| `preview_text` 计费 | 2 元/万字符（40 字 ≈ 0.008 元） |
| `t2a` 每次 6 积分 | 0.06 元/次，异步，要轮询 |
| voice_id 规则 | 英文 + 数字，字母开头 |
| 音色是账号级的 | 换机器不影响，但换 apiz 账号要重建 |

## 7. 一条被我写错、已更正的结论

旧版 `comic_tts.py` 的注释和本文档的上一版都写着：

> 不要用 `generate --model minimax/t2a`，后者是异步任务，只回 task_id，拿不到音频。

**这是错的。** `apiz tasks get <task_id>` 能取到 `result.audio_url`。
当初只看 `generate` 的即时返回就下了结论，没查 `tasks` 子命令，让这条错误
在文档里躺了整轮。以后凡是「拿不到结果」，先看 `apiz <cmd> --help` 里有没有
`tasks` / `get` 这一类，别急着归因为「网关不支持」。

## 8. 排查

| 现象 | 真因 | 处置 |
|---|---|---|
| `user_voices` 里没有新音色 | 没取任务结果，或任务失败 | `apiz tasks get <id>` 看 `status` / `success` |
| 音色过两天消失 | 168 小时未使用被回收 | 重跑 §1，描述用 §2 那段 |
| 念得像播报/像客服 | 描述缺「否定句」或写了「低沉/温柔」 | 加「不是在念稿，是在跟台下观众聊天」 |
| `emotion` 传了没反应 | 用的是 `speak`，它不支持 | 走 §5 的 `t2a` |
| t2a 报「voice_id 是必填参数」 | 套了 `voice_setting` 嵌套结构 | 参数放顶层 |
| 音色对但整体还是不脆 | `speed` 不是 1.0，或 `post_speed` 还在生效 | 两个都回 1.0，节奏交给文本 |
